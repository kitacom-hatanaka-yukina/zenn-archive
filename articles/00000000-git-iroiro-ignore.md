## はじめに

Git管理したくないファイルがあるときは .gitignore を使うのが一般的ですが
開発していく中で .gitignore だけは対応できないことも多いです
こんな時どうするっていうのをまとめてみました。

## 

方法	設定がGit管理される（他人にも影響）	Git登録済みに効く	Git未登録に効く	複数プロジェクト横断
プロジェクトの .gitignore	✅ される（コミットして共有）	❌	✅	❌（そのリポジトリのみ）
.git/info/exclude	❌ されない	❌	✅	❌
git update-index --skip-worktree	❌ されない	✅	❌	❌
グローバル .gitignore（core.excludesFile）	❌ されない（自分の端末だけ）	❌	✅	✅

確認と解除コマンドもここに書く

## プロジェクトの .gitignore

プロジェクトで管理する無視ファイルを管理する

node_moduleとかのような大きいファイル
.envのような気密性が高いファイル
キャッシュとかビルドファイルとか各個人がローカルで各々作るもの
などがGitに上がらないようにする

使う言語とかフレームワークによって大体テンプレみたいなのが決まっているので最低限設定しておくべし
.gitignore 自体がgitで管理されるので、個人の設定はここに書かない

未追跡ファイルにしか効かない
スデニGitに入っちゃってる追跡ファイルをこれからは無視したいって場合は、
.gitignoreに追加 + git rm --cached <ファイル> が必要
さらに今までの履歴からも一切合切消したいってときは完全に消すには git filter-repo や BFG が別途必要。

## .git/info/exclude

プロジェクトと一緒に管理したいけどGitに上げたくない自分用のファイルに使う

ローカルでのみ有効 ほかの人には影響しない
まだGitに上がっていないファイル（未追跡）にのみ使える

例えばこのプロジェクト専用の SKILLS 作ったんだけど、git上げるほどのものではないな～ってときとかに私は使う
あと自分用のbatとかスクリプトとか
既にgitに上がっているものには使えないのでその場合は以下の skip-worktree を使う

## git update-index --skip-ignore

既にgitに上がっているファイルを更新したけど、一時的にその変更を無視したいってときに使う

git update-index --skip-ignore ＜無視したいファイル＞

よく使うのが、設定ファイル等の一時的な変更
例えば、開発用にログ出力のフォーマットを使いやすいように変えたが、毎回変更に上がってくるのがうっとおしいみたいなとき

.git/info/exclude とは逆で 既に上がっているもののみが対象 新規ファイルには使えない

～を使って確認できる
～を使って解除できる

よく使うとは言ったものの乱用は厳禁
例えばローカルの実行ポートが開発メンバーによって違う！とかDBのパスが違う！とかみたいなことがある場合、
.env.template や config.ts.template みたいなファイル作って手元で設定ファイル作ってもらうような運用が推奨されている
ただ、世のなかのプロジェクトの全てがそのように整備されているわけではないし、
前述のログとかのように設定ファイルで管理されないがちな内容とかもあるので覚えておくと結構便利

戻し忘れには注意
skip-worktreeで設定しているファイルがリモートで更新されると git pull はエラーで止まる←要検討

ちなみに似た挙動をするものにものに --assume-unchanged もあるこれはパフォーマンス最適化用
前述のような使い方をするなら skip-worktree でいい

## グローバルの .gitignore

全てのプロジェクトで共通して無視したいファイルを設定できる

.gapaorice のようにプロジェクトで使われないであろうフォルダ名、拡張子 を設定しておくことで
memo.gapaorice のような仮ファイルを作ってめもしたり
.gapaorice フォルダを作って自分用のファイルの格納に使ったりできる

使い方としては .git/info/exclude と近いが、こちらは端末内で共通なので
一度登録するとどのプロジェクトでも有効になるのが便利

## ファイルの変更が上がってこない時の切り分け

では逆に無視したファイルを

mermaid→dwawioで図を描く

```
まず大枠：そのファイルは「追跡済み」か「未追跡」か

git ls-files <file> に出れば追跡済み → ケースB へ。出なければ未追跡 → ケースA へ。
ケースA：未追跡なのに git status に出てこない → gitignore 系で無視されている

git status --ignored … 無視されているファイルも含めて一覧表示。まず全体像を掴む。
git check-ignore -v <file> … どのファイルの何行目のルールで無視されているかを特定（.gitignore／グローバル／.git/info/exclude を区別できる）。
git ls-files --others --exclude-standard … 「無視されていない未追跡ファイル」の一覧。ここに出てこないなら、そのファイルは無視されている裏付け。
対応策：無視元のパターンを直す（該当する .gitignore／グローバル／.git/info/exclude を編集）。今回だけ例外的に追跡したいなら git add -f <file> で強制追加。
ケースB：追跡済みなのに変更が git status に出てこない → index フラグが付いている

git ls-files -v … 先頭フラグを確認。S=skip-worktree、h=assume-unchanged。git ls-files -v | grep -iE '^[Sh]' で該当ファイルだけ抽出。
対応策：git update-index --no-skip-worktree <file>（または --no-assume-unchanged）で解除すれば、変更が再び status に出る。
```
